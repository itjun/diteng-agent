# Windows 客户端试用验收

状态：**待用户在 Windows 实机执行**。macOS 本地测试和 Windows 安装包构建都不能替代这些结果。使用专用测试账号、测试账套及可撤销的测试单据；首次保存前确认当前账套。

开始前记录：客户端版本、Windows 版本/系统架构、是否从旧版本升级、测试账套别名 A/B、是否同时运行旧终端。账号和账套编号可用别名替代。不要提供密码、短信验证码、模型 Key、完整 sid/token、原始配置文件或含真实业务数据的截图。

| 项目 | 操作步骤 | 期望结果 | 失败时收集（脱敏） |
|---|---|---|---|
| 首次安装 | 安装提供的 x64 NSIS 包；启动后关闭再启动；查看任务管理器和系统启动应用 | 登录页可见，无空白窗；首次安装不主动启用开机启动 | 安装包文件名、客户端版本、系统架构、错误文字 |
| 账号密码 | 输入测试环境地址及测试账号；分别尝试错误密码和正确密码 | 错误可恢复；成功后进入正确账套，用户与账套名称正确 | 错误类型、是否可再次提交、身份展示的别名 |
| 新设备验证 | 使用服务端尚未认证的新测试设备登录；按界面发送/输入短信验证码 | 密码校验后才进入验证；错误/过期码不登录，正确码可登录；重复点发送遵守服务端限制 | 验证步骤和时间、错误文字，禁止验证码 |
| 记忆密码 | 分别测试记住密码/不记住、自动登录开/关；正常退出再重启；从历史账号切换 | 勾选状态、密码回填和自动登录符合选择；删除历史账号后不再回填；A/B账号不混用 | 勾选组合、重启方式、是否回填，禁止密码/配置文件 |
| 普通ERP与旧终端 | 登录新客户端，保持旧终端运行；在测试环境执行现有打印入口、串口扫码或称重入口 | 既有终端仍可接收和处理；新客户端不替代或改变旧终端设备配置 | 使用的模块、是否收到任务、脱敏错误；无设备时记为“未验证” |
| 切账套取消 | 在 A 打开三个标签并填写未保存内容；发起切 B；在桌面确认中取消 | 服务端身份仍是 A，标签保留，未保存内容保留；返回页面手动保存 | 切换入口、取消前后标签数、账套别名 |
| 切账套确认 | 从 A 的一个标签发起切 B；确认放弃未保存内容；切换等待时激活另一标签 | 先明确提示无法自动保存；核验成功后只保留发起标签，显示 B；不保留后来激活的旧标签 | 发起/活跃标签顺序、保留标签与账套别名 |
| 切换失败 | 测试环境模拟切换HTTP失败、短时断网；恢复网络后重试核验 | 不按HTTP失败猜身份；若服务端已变则落到新账套；身份未核验时阻止继续业务请求并提供重验/退出路径 | 断网和恢复时间、提示文字、恢复后的账套别名 |
| AI生成中切换 | 在 A 生成长回答，确认切 B | 未发出的操作与生成停止；旧片段不出现于 B；取消切换时身份不变 | 切换时生成状态、是否出现串账套片段（不提供内容） |
| 未决草稿切换/退出 | 使用测试草稿，提交期间让网络响应不确定；尝试切 B、退出登录、退出应用 | 保存结果未知时明确阻止切换/退出；提供回查，不自动重复提交；确认成功/失败后可以继续 | 请求ID（允许脱敏）、本地状态、回查结果，禁止token |
| 未决草稿登录过期 | 在 B 留下未知保存记录，让原登录过期后回查；先取消重新认证，再尝试不同主账号；最后用原账号重新认证（其默认账套为 A），按需完成新设备短信 | 401 后才出现恢复入口；取消/错误账号保留记录并仍阻止旧页面写入；原账号经授权换回原 B 及原子账号后只查询原请求ID，不自动再保存；失败可再次尝试 | 原/默认账套别名、错误类型、状态变化、脱敏请求ID、是否重复单据，禁止密码/验证码/token |
| 未发送成功的原ID重试 | 测试草稿提交前断网，使结果未知；恢复后先回查为未找到；按界面明确选择原请求重试，并快速双击；重启后再回查 | 不因一次未找到自动重提；明确操作后使用原 requestId、原提案及摘要，处理期间防重；最多一张草稿，重启仍可按原ID回查；不清库或产生新ID绕过 | 提交/断网/回查时间、脱敏请求ID是否相同、提示和草稿数量，禁止原始数据库/完整提案 |
| 普通通知 | 新旧客户端同时登录，让测试账号收到普通消息 | 新客户端系统通知与旧终端可各自提醒；不会因相同clientId互相挤下线；通知显示账套归属 | 消息等级、收到时间、两个客户端连接状态 |
| 紧急与日志 | 连续发两条紧急消息和一条日志级消息；等待超过一分钟；关闭首条 | 紧急提醒不抢焦点、不自动消失，后来的排队不覆盖首条；关闭后显示下一条；日志不触发紧急置顶 | 等级、队列计数、窗口行为；不提供正文 |
| 拒绝系统通知 | 在Windows设置中关闭新客户端系统通知，再发普通和紧急消息 | 不宣称系统通知已显示；普通消息仍可由角标/消息中心看到，紧急置顶开关独立生效 | 系统权限设置、客户端开关组合、可见行为 |
| 独立通知开关 | 分别切换客户端“系统通知”“紧急置顶”开关；旧终端保持运行 | 只影响新客户端对应展示；不修改旧终端提醒、不把消息标已读 | 开关组合、各客户端收到情况 |
| 通知跨账套 | 当前在 A，点击 B 的通知/紧急提醒；先取消切换，再确认切换 | 取消不关旧页、不改身份，紧急提醒保留；确认经统一核验后打开 B 的消息入口 | 通知账套别名、取消/确认后的身份与页面 |
| 断线与重启补偿 | 断网或完整退出后发送普通/紧急测试消息；恢复网络或重启；重复断网重连 | 授权账套的未读补回；历史普通消息不逐条轰炸，紧急消息进入持久队列；相同UID不重复入队；关闭提醒不等于业务已读 | 离线/恢复时间、消息等级/数量、队列恢复情况 |
| 托盘与明确退出 | 点击主窗关闭；再点托盘显示；最后选托盘退出 | 关闭仅隐藏，后台继续接消息；托盘可恢复主窗；明确退出停止本地Agent与MQTT，不残留窗口 | 托盘是否可见、任务管理器进程状态、退出提示 |
| 模型配置 | 配置测试模型Key，测试连通性；重启；切换另一个登录账号 | 测试结果明确；Key不在会话内容/日志显示；账号隔离；无Key时ERP仍可使用 | 服务商名称、模型名称、脱敏错误，禁止Key/Base URL凭据 |
| 附件与页面 | 添加小型测试图片/CSV或XLSX；主动附上当前页文本/截图；检查预览再发送 | 大小/格式限制清楚；先有预览；不自动读取磁盘或别的标签；隐藏DOM与输入值不进入文本资料；截图须自行检查业务隐私 | 文件格式/大小、是否有预览、错误文字；不提供真实附件 |
| 草稿确认与防重 | 让助手提出测试销售订单；核对客户/商品/数量；在确认前验证ERP无新增；确认保存时快速连点/回车 | 提案阶段不写；确认后最多一张未审核草稿；不自动审批；响应不确定只回查原请求 | 请求ID、草稿数量、状态及脱敏单据号 |
| 手工升级 | 在旧版保存测试聊天/模型设置/未决状态；退出后安装新版；重开并登录同一测试账号 | 本地会话与凭据按账号恢复；未决写状态仍待回查；升级不能清空数据以“修复”；不运行两个版本争写本地数据 | 升级前后版本、保留/丢失的数据类别，禁止原始数据库/配置 |

每项记录“通过 / 失败 / 未验证”、测试时间、版本和简短观察。系统通知API被调用不代表Windows实际展示；紧急弹窗和消息中心也不能代替服务端已读状态。若出现串账套、重复草稿或未决写被绕过，停止该测试账号后续写入，保留脱敏步骤与请求ID交给开发者定位。
